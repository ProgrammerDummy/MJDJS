MJDJS Project File Structure (end of Week 4)

This reflects what we built together in this conversation. I don't have live
access to your actual filesystem, so treat this as a reference to check against
your real repo, not a guaranteed-exact snapshot — things like your .git internals,
editor config files, or anything outside what we directly discussed aren't
represented here.

MJDJS/                                 <- virtual Cargo workspace root: no [package],
│                                          no root src/, nothing compiles at this level
│
├── Cargo.toml                         <- [workspace] + [workspace.dependencies] only
├── Cargo.lock
├── .gitignore                         <- should exclude target/ in every crate
│
├── reference/                         <- NOT a workspace member, nothing here compiles.
│   │                                     Old Phase 1 in-process scheduler, kept only
│   │                                     for pattern reference (cancellation racing,
│   │                                     the Abandoned-state design). Expect real
│   │                                     redesign, not a literal port, once Week 5's
│   │                                     dispatch model replaces this.
│   ├── scheduler.rs                   <- old Scheduler<T>, tokio::select! dispatch
│   │                                     loop, graceful shutdown logic
│   └── worker.rs                      <- old WorkerPool<T: Runnable>, Worker
│
├── scheduler-core/                    <- lib crate. Owns the proto schema and all
│   │                                     codegen. Every other crate depends on this
│   │                                     one; it depends on none of them.
│   ├── Cargo.toml
│   ├── build.rs                       <- runs tonic-prost-build against
│   │                                     proto/scheduler.proto. Lives at the crate
│   │                                     root, NOT inside src/.
│   ├── proto/
│   │   └── scheduler.proto            <- the full gRPC schema: SchedulerService,
│   │                                     WorkerService, every message, every oneof
│   └── src/
│       ├── lib.rs                     <- module declarations, plus
│       │                                 `pub mod proto { tonic::include_proto!("scheduler"); }`
│       ├── job_data_structures.rs     <- Job, JobState, RetryPolicy, JobQueue,
│       │                                 now_millis()
│       ├── state_machine.rs           <- JobEvent, TransitionError, transition(),
│       │                                 determine_next_event(), full test suite
│       └── conversion.rs              <- ConversionError, TryFrom<Job> for
│                                         proto::Job and the reverse, plus the
│                                         extracted helpers job_state_to_proto()
│                                         and proto_to_job_status()
│
├── scheduler-server/                  <- bin crate. The actual gRPC server process.
│   ├── Cargo.toml
│   └── src/
│       ├── main.rs                    <- stands up tonic::transport::Server, binds
│       │                                 to SCHEDULER_ADDR (env var, with a
│       │                                 hardcoded fallback)
│       └── service.rs                 <- MySchedulerService (implements the
│                                         generated SchedulerService trait).
│                                         submit_job and get_job_status are fully
│                                         implemented and tested. The other five
│                                         RPCs are honest Status::unimplemented
│                                         stubs. Also holds validate_retry_policy()
│                                         and the integration test suite.
│
├── worker-agent/                      <- bin crate. Not yet built out beyond the
│   ├── Cargo.toml                        default skeleton. Will be the gRPC
│   └── src/                              *client* for WorkerService — workers
│       └── main.rs                       dial the scheduler, not the reverse.
│                                         (currently just the default placeholder)
│
└── scheduler-client/                  <- lib crate (likely gaining a CLI bin
    ├── Cargo.toml                        target later). Not yet built out beyond
    └── src/                              the skeleton. Will be a typed
        └── lib.rs / main.rs              SchedulerService client wrapper meant to
                                          be reused by a future CLI and eventually
                                          a web dashboard.
                                          (currently just the default placeholder)

Notes:
- Each crate's target/ directory (build output) is omitted here deliberately —
  it's generated, not authored, and should be gitignored.
- Dependency direction is strictly hub-and-spoke: scheduler-server, worker-agent,
  and scheduler-client each depend on scheduler-core via a path dependency; none
  of the three depend on each other.
- If your actual repo has anything not listed here (extra resource folders,
  scratch files, etc.), that's expected — this covers what we deliberately built
  and discussed, not necessarily every file in the tree.
